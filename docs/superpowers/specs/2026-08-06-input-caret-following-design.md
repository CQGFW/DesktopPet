# 输入光标跟随设计

## 目标

在当前前台应用的文本控件接收键盘输入时，让桌面宠物跟随插入光标移动，并临时缩小到进入输入状态前缩放值的 20%。宠物必须避开输入控件和输入法候选区域；输入结束后恢复进入输入状态前的缩放和脚底位置。

## 范围与约束

- 对所有前台应用的文本控件生效，包括记事本、浏览器、IDE、聊天框等。
- 复用现有 Windows 全局低阶键盘钩子，不新增第三方 Python 依赖。
- 默认使用 1000ms 无按键作为输入结束判定。
- 输入跟随不受“键盘互动”开关和“减少动态效果”设置影响；后者仍只控制装饰性动画。
- 用户点击、拖拽或滚轮操作宠物时立即结束输入跟随。

## 方案

在 `pet_v2.py` 中加入 Win32 光标查询组件和 `Pet` 输入跟随状态，不拆分新的运行时模块，以保持当前单文件 PyInstaller 配置。

### 光标查询

查询前台窗口所属线程的 `GUITHREADINFO`，取得 `hwndCaret` 和 `rcCaret`。通过 `ClientToScreen` 将光标矩形转换为屏幕坐标，并读取 `hwndFocus` 的窗口矩形作为输入控件避让区域。

传统 IME 通过 `ImmGetContext` / `ImmGetCandidateWindow` 查询候选区域。所有 Win32 调用都封装为可失败查询，句柄为空、API 失败或坐标无效时返回 `None`，不让异常穿透 Qt 事件循环。

### 状态与时序

`Pet` 增加以下状态和定时器：

- `input_follow_active`：是否处于输入跟随状态；
- `input_saved_scale`、`input_saved_foot`：进入状态前的缩放值和脚底中心坐标；
- 单次无按键定时器，间隔 1000ms；
- 约 50ms 的光标轮询定时器，用于在按键事件先于目标应用更新光标时补偿刷新。

全局键盘钩子收到按键后先调用输入跟随入口，再执行现有 BongoCat 脚掌逻辑。第一次成功查询光标时保存当前几何状态并将缩放设置为 `input_saved_scale * 0.2`；后续按键只重置超时并刷新位置。轮询发现前台已无有效文本光标时结束跟随并恢复保存的状态。

恢复时先通过现有脚底锚定缩放逻辑恢复尺寸，再移动到保存的脚底坐标，确保窗口不会因尺寸变化漂移。

### 定位与避让

使用缩小后的宠物窗口完整矩形进行保守碰撞检测：

1. 首选宠物水平中心对齐光标中心，顶部位于光标底部下方约 12px。
2. 若与输入控件矩形相交，下移到输入控件底部并留出间距。
3. 若与 IME 候选区域相交，下移到候选区域底部并留出间距；重复检查直到不相交。
4. 水平方向限制在当前屏幕可用区域内。
5. 屏幕底部空间不足时，按“光标上方、光标左右侧”顺序尝试可用位置，并继续执行碰撞检测。

光标暂时不可读时保留最后安全位置，避免抖动；无按键超时、焦点丢失或宠物操作会结束状态并恢复原位置。

## 测试

在 `selftest_v2.py` 中增加：

- 光标下方首选位置、输入控件和候选区域碰撞避让、屏幕边界回退的几何测试；
- 临时缩放为进入前值 20% 的断言；
- 首次进入保存状态、连续按键不覆盖基准、超时完整恢复、宠物操作立即退出的状态测试；
- Win32 查询失败和无光标句柄的安全降级测试。

保留现有全量回归用例。Windows 手工验收覆盖记事本、浏览器、IDE、中文 IME 候选、多行编辑器、多显示器和屏幕底部边缘。

## 风险与降级

不同应用对 Win32 光标和 IME 接口的支持程度不同。无法读取光标或候选区域时不抛异常、不改变未激活状态；已激活后查询暂时失败只保留最后位置，确认失去焦点或超时后恢复。UI Automation 不作为本次实现依赖，保留为未来兼容性扩展方向。
