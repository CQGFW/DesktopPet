# 可调整的输入跟随大小设计

## 目标

让用户可以调整宠物在输入跟随状态下的大小。当前该大小写死为「进入输入前缩放值的 20%」（`config.INPUT_SCALE_FACTOR`），用户无法更改。

改为在右键菜单里从四个预设档位中选择，档位为**绝对缩放比例**，与宠物平时的大小无关。

## 范围与约束

- 只改变输入跟随状态下的目标缩放值；进入 / 退出跟随的时机、落位避让、还原逻辑均不变。
- 档位是离散预设，不提供连续调节（滚轮在跟随状态下仍然是「退出跟随」，行为不变）。
- 档位选择随其他偏好一起持久化，下次启动沿用。
- 不引入新的第三方依赖，不触碰 Win32 / UIA / 候选框探测各层。

## 方案

### 档位定义

在 `desktoppet/config.py` 中，用两个常量取代原来的 `INPUT_SCALE_FACTOR`：

```python
INPUT_SCALE_CHOICES = (0.20, 0.25, 0.30, 0.40)
INPUT_SCALE_DEFAULT = 0.20
```

按 `BASE_H = 260` 换算的实际猫高：

| 档位 | 猫高 |
| --- | --- |
| 20%（默认） | 52px |
| 25% | 65px |
| 30% | 78px |
| 40% | 104px |

默认值 20% 与改动前在平时缩放 100% 下的观感完全一致，因此老用户升级后不会感到大小突变。

不提供 15% 及以下的档位：实测 21~39px 时猫的细节已经无法辨认，身前键盘的留白只剩 3~5px，实际不可用。

### 语义：绝对比例

改动前跟随大小是 `input_saved_scale * 0.2`，即相对倍率——平时把宠物调到 25% 时，跟随大小只有 5%（约 13px），几乎不可见。

改为绝对比例后，跟随大小恒等于所选档位，与平时大小解耦。代价是平时把宠物调大后，跟随时不再按比例变大；收益是「选多大就是多大」，且不存在小到看不见的组合。

### 状态与应用

`Pet` 新增 `input_follow_scale` 字段，保存当前档位。`_input_on_key` 中：

```python
self._set_scale(self.input_saved_scale * config.INPUT_SCALE_FACTOR)   # 改动前
self._set_scale(self.input_follow_scale)                             # 改动后
```

`input_saved_scale` 的职责不变——仍然记录进入跟随前的平时比例，供退出时还原。`_stop_input_follow`、`_persistable_scale` 均不改动。

### 菜单

右键菜单在「输入跟随」之后新增子菜单「输入跟随大小」，四个档位用 `QActionGroup` 组成互斥选项（radio 样式），当前档位打勾。菜单项文本为百分比，如 `20%`。

子菜单是本项目菜单里的新结构（此前是平铺列表），但沿用相同的「创建 → setChecked → 连信号」顺序，避免构造期触发槽。

「输入跟随」开关关闭时，子菜单**保持可用**，不置灰。档位是一项独立的存储偏好，用户可以先设好大小再开启跟随；置灰需要额外维护两个菜单项之间的联动状态，收益不足。

### 不实现：跟随中实时改档位

`contextMenuEvent` 在弹出菜单前会先调用 `_stop_input_follow()`，因此用户不可能在跟随进行中打开菜单。「改档位后立即重新缩放当前跟随」这条路径只有测试能触发，属于无用功。

改档位的处理因此简化为：赋值 `input_follow_scale`，调用 `_schedule_save()`，下次输入时自然生效。

### 持久化

`settings.DEFAULTS` 当前是纯 bool 字典，新增项是浮点数，因此像 `scale` 一样在字典之外单独处理，键名 `input_scale`。

校验规则比 `scale` 更严：读回的值必须落在 `INPUT_SCALE_CHOICES` 集合内，否则退回 `INPUT_SCALE_DEFAULT`。理由是它是离散档位而非连续值——一个不在集合内的值（来自旧版本或被手工改坏的配置）会导致菜单中没有任何一项处于选中态，界面进入无法自解释的状态。

`settings.load()` 的返回值从 `(flags, scale)` 扩展为 `(flags, scale, input_scale)`，`save()` 相应增加一个参数。调用点只有 `Pet.__init__` 与 `Pet.save_settings` 两处。

## 边界情况

- **档位低于平时缩放下限**：20% 低于 `MIN_SCALE`（25%）。这是改动前就存在的情况（原本的 0.2 同样低于 0.25），因为 `_set_scale` 自身不做钳制，钳制只发生在 `wheelEvent` 里。档位不经过滚轮路径，因此安全。
- **跟随中存盘**：`_persistable_scale()` 在跟随中返回 `input_saved_scale`，不会把档位误存成平时大小。该行为已有测试覆盖，本次不改。
- **退出还原**：还原目标始终是 `input_saved_scale`，与档位无关，因此改档位不影响任何退出路径。

## 测试

在 `tests/` 下扩充，全部可在 offscreen 下运行：

- 选中某档位后进入跟随，实际缩放等于该档位。
- **绝对语义**（与旧的相对倍率行为的分界）：把平时大小分别设为 `MAX_SCALE` 与 `MIN_SCALE`，跟随大小仍等于档位。
- 回归：各退出路径仍还原平时大小与脚底锚点。
- 持久化往返；不在 `INPUT_SCALE_CHOICES` 内的值退回默认。
- 菜单：子菜单包含四个档位、互斥、当前档位处于选中态。
- 默认档位等于 `INPUT_SCALE_DEFAULT`，且该值在 `INPUT_SCALE_CHOICES` 内。

## 风险与降级

改动集中在 `config.py` / `settings.py` / `pet.py` 三个文件，不涉及 Win32、UIA、候选框探测等只能在真机验证的层次，因此可由自动化测试完全覆盖。

主要风险是 `settings.load()` 签名变化遗漏调用点；调用点仅两处，且返回值元组长度变化会立即触发解包错误，不会静默失败。

`config.INPUT_SCALE_FACTOR` 被删除后，现有的 `tests/test_input_follow.py` 中引用它的断言需同步改为按档位判定——该文件的其余用例（各退出路径的还原契约）保持不变。
